Componentes

🗄️
Model
portfolio/models.py

Define a estrutura dos dados. Cada classe Python corresponde a uma tabela na base de dados. O ORM do Django traduz as operações Python em SQL automaticamente — não é necessário escrever SQL diretamente.

Projeto.objects.all()
⚙️
View
portfolio/views.py

Recebe o pedido HTTP, consulta os Models, processa a lógica de negócio e devolve uma resposta. É o intermediário entre os dados e a apresentação. Nunca contém HTML.

render(request, 'template.html', contexto)
🎨
Template
templates/portfolio/*.html

Ficheiro HTML com sintaxe Django que apresenta os dados. Recebe o contexto da View e renderiza o HTML final. Não faz queries nem processa lógica complexa.

models.py

portfolio/models.py
class Licenciatura(models.Model):
    nome = models.CharField(max_length=200)
    sigla = models.CharField(max_length=20)
    url_site = models.URLField(blank=True)
    imagem = models.ImageField(upload_to='licenciatura/', blank=True)

class UnidadeCurricular(models.Model):
    licenciatura = models.ForeignKey(Licenciatura, on_delete=models.CASCADE)
    docentes = models.ManyToManyField('Docente', blank=True)
    nome = models.CharField(max_length=200)
    ano = models.IntegerField()
    semestre = models.IntegerField()
    ects = models.IntegerField(default=6)
    objetivos = models.TextField(blank=True)
    programa = models.TextField(blank=True)

class Projeto(models.Model):
    uc = models.ForeignKey(UnidadeCurricular, on_delete=models.CASCADE)
    titulo = models.CharField(max_length=150)
    descricao = models.TextField()
    link_github = models.URLField(blank=True)
    tecnologias = models.ManyToManyField('Tecnologia')
    competencias = models.ManyToManyField('Competencia', blank=True)

class Tecnologia(models.Model):
    nome = models.CharField(max_length=100)
    tipo = models.ForeignKey('TipoTecnologia', on_delete=models.SET_NULL, null=True)
    descricao = models.TextField(blank=True)
    logo = models.ImageField(upload_to='tecnologias/', blank=True)
    nivel_interesse = models.IntegerField(default=3)

Como foi usado o Git e GitHub

📦

Controlo de versões

Cada funcionalidade implementada foi guardada com um commit descritivo. Isto permite reverter para qualquer versão anterior caso algo corra mal.

☁️

Backup automático

O código está sempre seguro no GitHub — mesmo que o Codespace seja apagado, o trabalho não se perde. O push regular foi uma prática essencial.

🌐

Codespaces

O GitHub Codespaces permite desenvolver diretamente no browser, sem instalar nada localmente. Todo este projeto foi desenvolvido no Codespace associado a este repositório.

📋

Histórico de commits

O histórico de commits documenta a evolução do projeto — cada mensagem descreve o que foi implementado, tornando fácil perceber o progresso ao longo do tempo.

Comandos git usados regularmente
git add *                          # adiciona todos os ficheiros alterados
git commit -m "mensagem clara"     # guarda as alterações localmente
git push -u origin main            # envia para o GitHub
git pull origin main               # recebe alterações do GitHub
